# RafGitTools — Commit Evidence Gate V1

Status: `IMPLEMENTED_SOURCE / PRE_ARTIFACT_SOURCE_GATE_WIRED / HUMAN_SAFEGUARDS_UNBOUND / EXACT_HEAD_CI_PENDING / CLAIM_ALLOWED=false`

## Objective

Reduce uncertainty before promoting a governed Git change. The gate does not claim absolute truth or absolute failure-proofing. It constrains promotion so that unknown or missing evidence remains explicit and blocks higher-risk transitions.

```text
HUMAN_DIGNITY > DELIVERY_SPEED
CHILD_SAFETY > FEATURE_COMPLETION
UNKNOWN_HUMAN_IMPACT != SAFE
AI_ASSESSMENT != HUMAN_AUTHORITY
UNKNOWN != PASS
TOKEN_VAZIO != 0
SOURCE != ARTIFACT != EXECUTION != EVIDENCE != CLAIM
PUBLIC_PROOF != PUBLIC_PAYLOAD
AI_GENERATED != VERIFIED
```

## Human-first non-compensatory boundary

Human dignity is evaluated before PRE/ACT/POST promotion. The following safeguards are required for Draft, Ready and Merge:

- `HUMAN_DIGNITY`
- `CHILD_SAFETY`
- `INCLUSION_NONDISCRIMINATION`
- `ACCESSIBILITY_INCLUSION`
- `SAFE_HEALTHY_WORK`

`FAIL`, `TOKEN_VAZIO`, `NOT_RUN` or `NOT_APPLICABLE` in any required human safeguard blocks promotion. Technical PASS values cannot compensate for one unresolved human safeguard.

A human-safeguard `PASS` must contain traceable human authority, proof, typed risk severity, typed urgency, falsifier and mitigation reference. Supporting evidence may be generated by AI/automation/provider, but an AI or automation does not self-certify the human safeguard boundary.

The live UI currently has no connected human-safeguard receipt adapter, so these checks are intentionally emitted as `TOKEN_VAZIO`. This is a visible gap, not a silent assumption of safety.

Normative reference anchors are documented in `docs/architecture/HUMAN_DIGNITY_SAFEGUARD_V1.md`. They are anchors for governance design only; this repository does not claim certification or complete legal/jurisdictional compliance.

## Placement

The gate is instantiated inside the existing `WorkspaceEditorScreen` so it reads the exact same `WorkspaceEditorUiState`. It does not create a second workspace and does not execute GitHub writes itself.

Authorized execution remains in the governed RafGitFS flow:

```text
private workspace
→ staged files
→ base SHA / three-way comparison
→ canonical plan
→ DRY_RUN
→ exact approval bound to planHash
→ rafgitfs/* branch
→ atomic commit
→ non-force push
→ draft PR
→ append-only receipt
```

## AI / multi-agent boundary

Human, AI-agent, automation, provider and external registry are represented as producers with explicit independence domains.

```text
AI_GENERATED != VERIFIED
PRODUCER_IDENTITY != REVIEW_AUTHORITY
MANY_AGENTS != MANY_INDEPENDENT_WITNESSES
AI_ASSESSMENT != HUMAN_AUTHORITY
```

The same producer cannot satisfy source authorship and independent review for a critical merge decision. Trusted-time and transparency witnesses must also not collapse to the same independence domain. For human-first safeguards, PASS additionally requires a human producer/authority.

## Three phases

### HUMAN-FIRST — dignity and social safeguards

Required before Draft may be permitted:

- dignity impact assessed;
- child-safety/best-interest relevance assessed;
- inclusion and non-discrimination assessed;
- accessibility/inclusion assessed;
- safe and healthy work impact assessed.

No `NOT_APPLICABLE` shortcut is accepted for these required safeguards. A no-impact conclusion is represented as PASS only after a scoped, traceable human assessment.

### PRE — anteriority and boundary

Required before a draft may be published:

- repository + ref identity;
- private workspace identity;
- observed base commit;
- unresolved three-way conflict count = 0.

### ACT — exact authorized transition

Required before execution:

- canonical `planHash` exists;
- exact human approval matches the current planHash;
- no direct main write, force-push or remote delete is permitted by the RafGitFS contract.

Any material plan change invalidates the approval.

### POST — evidence before stronger promotion

Required before promotion beyond draft:

- execution receipt observed;
- CI bound to exact PR head;
- server-side enforcement read back from provider;
- independent trusted-time evidence;
- append-only transparency-log inclusion proof;
- independent review.

Scientific/publication provenance additionally requires at least one typed publication witness when the `SCIENTIFIC_PUBLICATION` profile is selected.

## Promotion lattice

```text
DRAFT_ALLOWED
  requires HUMAN-FIRST + PRE + ACT

READY_ALLOWED
  requires DRAFT_ALLOWED + observed execution receipt + exact-head CI

MERGE_ALLOWED
  requires READY_ALLOWED
  + server enforcement
  + trusted time
  + transparency proof
  + independent review
  + typed publication anchor when profile=SCIENTIFIC_PUBLICATION
```

No score can compensate for a missing critical requirement.

```text
100 local PASS != one critical TOKEN_VAZIO
1000 copies != 1000 independent witnesses
CI_GREEN != HUMAN_SAFETY_CLEARANCE
```

## Time and anteriority

Git commit timestamps are useful metadata but are not treated as sufficient real-world time evidence.

The target model is multi-anchor rather than a private blockchain:

```text
artifact digest
+ Git blob/tree/commit identities
+ signed TSA timestamp (RFC 3161 class)
+ transparency-log inclusion/consistency proof
+ optional DOI/publication metadata
= stronger anteriority evidence
```

No single clock, registry, chain, AI, provider or publication is promoted to absolute authority. Independent anchors reduce correlated failure and tampering risk.

Publication dates are typed. `registered`, `created`, `issued`, `published-online`, `accepted` and similar meanings must not be collapsed into one unqualified date.

## Privacy boundary

Public anchoring MUST minimize disclosure. External services should receive only the digest/attestation material needed for verification; private source payloads, secrets, local paths and unnecessary metadata must not be published.

```text
PUBLIC_PROOF != PUBLIC_PAYLOAD
absolute_privacy = false
privacy_minimization = measurable objective
```

## Pre-artifact source validation

`scripts/validate_commit_evidence_gate_v1.py` is invoked inside the local `workflow-graph-audit` composite action before `actions/upload-artifact`.

This deliberately separates:

```text
SOURCE_GATE_RESULT != ARTIFACT_UPLOAD_RESULT
```

The validator now also requires the HUMAN-FIRST safeguard types, risk/urgency typing, falsifier tests, human-safeguard documentation, and UI exposure. If these disappear, source validation fails before artifact upload.

If GitHub artifact quota fails after the validator ran, source evidence remains observable in the job log and the generated local receipt, while downstream tests remain `NOT_RUN`/`TOKEN_VAZIO` rather than being promoted to PASS.

## Falsifiers implemented in source tests

1. missing human dignity evidence must block Draft/Ready/Merge;
2. `CHILD_SAFETY=FAIL` must block all promotion;
3. human safeguards cannot bypass the boundary with `NOT_APPLICABLE`;
4. AI cannot certify a human-safeguard PASS;
5. human safeguard PASS without risk typing remains unresolved;
6. exact-head CI with the wrong head SHA must block Ready/Merge;
7. `TRUSTED_TIME=TOKEN_VAZIO` must block Merge;
8. trusted-time and transparency proofs from the same independence domain must be rejected;
9. source producer cannot self-satisfy independent review;
10. `privatePayloadIncluded=true` must fail closed;
11. scientific profile requires typed publication date;
12. AI generation and AI verification with the same producer identity must be rejected as independent review.

## Remaining falsifiers / evidence gaps

1. connect real human-safeguard assessment receipts and independently review their adequacy;
2. mutate `planHash` after approval and verify draft becomes blocked in the UI/ViewModel integration path;
3. introduce unresolved three-way conflict and verify draft becomes blocked;
4. connect real provider evidence and reject stale/non-head CI;
5. connect RFC 3161-compatible evidence and reject invalid signature/time binding;
6. connect transparency evidence and reject missing inclusion/consistency proof;
7. verify external anchoring transmits only minimized digest/attestation material;
8. execute Android/JVM tests on the exact PR head after provider artifact capacity is restored or a non-weakening evidence sink is available.
